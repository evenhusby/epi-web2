# epiport.org (v2)

Institutional site for EPI AS — static Astro frontend + nightly-generated
public data. See `epiport-handoff.md` for the full brief (architecture,
design tokens, content, and open TODOs) and `epiport-prototype.html` for
the original self-contained visual reference this was ported from.

## Structure

- `src/pages/index.astro`, `src/pages/en/index.astro` — the two locales
  (`no` at `/`, `en` at `/en/`), via Astro's built-in i18n routing.
- `src/components/` — Hero, MapApp (stat band + interactive map + port
  panel), About, Roles.
- `src/lib/map-app.ts` — the interactive map/panel: Mapbox GL JS
  (`light-v11` style, layer-hiding to cut street/POI/building clutter),
  click-to-select a port via feature-state, aggregate view when nothing's
  selected. (Was a D3 illustration for the initial scaffold; swapped to
  Mapbox after reviewing the old Squarespace site's map code — see below.)
- `src/lib/i18n.ts` — the NO/EN string dictionary.
- `public/api/summary.json`, `public/api/ports.geojson` — placeholder data
  matching the documented contract; baked into the static build. Replace
  with real output from `tools/generate_public_json.py` once wired up.

## Develop

```
npm install
cp .env.example .env   # fill in PUBLIC_MAPBOX_TOKEN
npm run dev
```

`PUBLIC_MAPBOX_TOKEN` needs a Mapbox token scoped to this project's domains
(not the old Squarespace site's token — that one's tied to its own billing
and domain restrictions). Without it the map area shows a plain "unavailable"
message and the rest of the page still works.

### On the map: why Mapbox, not D3

The original prototype's map was a hand-drawn D3 illustration (placeholder
coastlines, flat projection). The old Squarespace site used real Mapbox GL
JS vector tiles instead, which is why it looked more accurate — that's not
a special projection, just a real basemap vs. a sketch. We kept the Mapbox
approach here: `mapbox://styles/mapbox/light-v11` as a base, with a
best-effort layer-hiding pass (`NOISY_LAYER_PATTERN` in `map-app.ts`) to
strip street/POI/building noise down toward the editorial ink-on-paper
look. That heuristic is not a substitute for a proper custom Mapbox Studio
style built to match the `--papir`/`--blekk`/`--gronn` tokens exactly —
worth doing once the design needs to be pixel-tight.

We did **not** reuse the old site's data APIs (`bergenhavn-...vercel.app`,
`epifapiprod.azurewebsites.net`, `api.flamport.no`) per instruction — those
are being retired. Port/summary data still comes from `public/api/*.json`,
meant to be regenerated by the nightly `tools/generate_public_json.py`
job against epi_v2 directly (see below), not fetched from those APIs.

## Deploy (Railway)

The `site` service is connected directly to this repo (`evenhusby/epi-web2`
@ `main`) as its source and auto-deploys on push, building via Railway's
own Railpack detection (not a repo Dockerfile — an earlier `railway.toml` +
`Dockerfile` pair mirroring epi-pilot's config-as-code pattern was removed
once the GitHub-source connection made them dead code).

`railway.cron.toml` + `Dockerfile.cron` + `tools/generate_public_json.py`
remain as a nightly job scaffold for the epi_v2 export, for a separate
Railway service that hasn't been created yet. **Not wired end-to-end** —
see the docstring in `generate_public_json.py` for what's left (real
epi_v2 queries, and a decision on how the generated files reach the live
site: shared Volume + small read API, or a data-only commit that triggers
a rebuild).

No hardcoded Railway tokens or project/service IDs in this repo — set
`RAILWAY_API_TOKEN` etc. as Railway environment variables if/when the
redeploy-trigger path is wired up, not in source. Same for
`PUBLIC_MAPBOX_TOKEN` on the site service — set it in Railway's env vars,
since Astro inlines `PUBLIC_*` vars at build time.

## Known gaps (from epiport-handoff.md, plus what changed here)

1. DNV wording needs revisiting at the 2027 handover.
2. Which per-port fields are public (esp. `avg_score`) isn't settled.
3. `tools/generate_public_json.py` has placeholder SQL — needs the real
   epi_v2 schema.
4. ~~Coastlines are a hand-drawn illustrative placeholder~~ — resolved:
   swapped to Mapbox GL JS real vector tiles. Remaining: the `light-v11`
   layer-hiding pass is a rough cut, not a tuned custom style.
5. No redirect map from the old Squarespace URLs yet.
6. Full port list/coordinates should come from the database/WPI, not the
   17-port placeholder set carried over from the prototype. (The old
   Squarespace site's ports API has real, richer data — SDG flags, shore
   power, memberships — but per instruction we're not depending on that
   API; `generate_public_json.py` still targets epi_v2 directly.)
7. The map hasn't been visually verified in this session — this sandbox's
   network policy blocks `api.mapbox.com` outright, so I could only
   type-check the Mapbox integration (`astro check` + `tsc --noEmit`, both
   clean), not see it render. Test locally with a real
   `PUBLIC_MAPBOX_TOKEN` before treating the map as done.
